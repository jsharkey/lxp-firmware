# EG4 6000XP (`ccaa`) — adding a third model

Analysis of the EG4 6000XP ARM "com" image (`…_ccaa-xx15xx_260519.hex`) and the
basis for its entry in the variant abstraction (`include/inv/variant.h`,
`src/variant.c`, `make VARIANT=6000xp`).

**Verdict: same MCU, same codebase — a drop-in third variant.** All structural
facts below are direct reads of the image (via `tools/hex2bin.py` + `tools/vt.py`).

## Same family as the already-supported models

| property | 6000XP | how we know |
|---|---|---|
| MCU | STM32F103 high-density, Cortex-M3 | `RCC @0x40021000`, `FLASH_ACR @0x40022000` in literal pools (F1-only) |
| C runtime | Keil armcc, scatter-loaded | reset stub is the identical `ldr;blx`→SystemInit / `ldr;bx`→`__main` idiom |
| Model code | `ccaa` | string in image |
| Image signature | `SNCC` (`0x0803F7FC`) | cf. `SNEC` (12000XP), `EAA1` (18kPV) |
| Codebase era | 07-series | shares the `…SNDPOTatezLAA1SA22` marker introduced in the 12000XP 07xx (absent in 05xx) |

## Boot layout — bootloader + App (same shape as the 12000XP 07-series)

| | value |
|---|---|
| Vector table / VTOR | **`0x08005000`** |
| Low 20 KB `0x08000000..0x08004FFF` | absent — reserved for a bootloader (all `0xFF`) |
| Initial MSP | `0x2000AF88` |
| Reset handler | `0x0802B064` |
| App top | `0x0803F7FF` (256 KB boundary; `SNCC…` signature block at `0x0803F600`) |

`SystemInit` writes `SCB->VTOR = 0x08005000` (literal at `0x080249DC`,
`SCB->VTOR`=`0xE000ED08` referenced at `0x080320C8`). This is the same
`layout = INV_IMAGE_APP_OVER_BL` / relocated-vectors design as the 12000XP
07-series (`docs/11-12000xp-revisions.md`) and the 18kPV
(`docs/10-18kpv-vs-12000xp.md`) — only the bootloader size differs
(`0x5000` here vs `0xC800` on the 18kPV).

## Topology is spec-derived, not an in-band read

Like the 18kPV App, this App partition does **not** embed the HMI string/font
tables — only ~295 mostly-noise strings extract (vs ~950 from the monolithic
12000XP), so MPPT count, phase and hybrid flag could **not** be confirmed from
the image. The descriptor uses the EG4 6000XP product spec:

- 6 kW off-grid all-in-one, **2 MPPT**, **non-hybrid**, split-phase 120/240 V,
  generator input + generator-charge.

These are the values a 6000XP shares with the 12000XP class (minus the power
rating); they should be confirmed against a resource/bootloader dump or a live
unit. The firmware consequences are the same as the 12000XP: the 3rd-MPPT
Modbus registers are gated off by `inv_ir_active()`, and the hybrid-only
features are disabled.

## Build

```bash
make VARIANT=6000xp   # vectors @0x08005000, 20 KB bootloader reserved, 256 KB part
```

Flash the resulting image to `0x08005000` (the bootloader below it is not part
of this build).
