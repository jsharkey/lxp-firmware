## How this firmware is built (affects RE technique)

It is **Keil/armcc**, and almost every inter-function call is **indirect**:

```
ldr  rX, [pc, #imm]   ; load a function pointer from the literal pool
blx  rX               ; call through it
```

So a naive "follow BL" disassembler recovers almost nothing (it did: 30
functions). `recurse.py` therefore also treats **odd (Thumb) code pointers
found in literal pools** as function entries — that is how the firmware itself
reaches its code — plus a `push {...,lr}` prologue scan for anything still
missed. That combination is what lifts coverage to ~72%.

## String references & naming — the addressing fix

An earlier version of this doc concluded that HMI strings were "not statically
referenced" and that binding them to functions needed dynamic analysis. **That
was wrong — it was an artifact of the non-contiguous `.bin`** (see `docs/01`).
The code references strings by their *true* flash address; on the gap-stripped
`.bin` those addresses were shifted by `+0x2400`/`+0x3600`, so nothing matched.

On the correctly-addressed flat image everything resolves:

- `"Battery Type: "` is at **`0x0803cfb8`** (not `0x080399b8`) and is referenced
  by a literal word at `0x080060c0`.
- The HMI **does** use `const char*` pointer tables — e.g. the menu table at
  `0x080060a4`: `"SN: "`, `"FW: "`, `"Set Time: "`, `"Lead-acid Capacity: "`…
  (14 such tables into the string region).
- `recurse.py` now finds **136 string xrefs**; `xref.py` names **13 functions**
  directly from the menu text they use.

### Named menu handlers (examples)
`fn_Hybrid_Setting`, `fn_Parallel_Setting`, `fn_Smart_Load`, `fn_AC_Couple`,
`fn_Meter`, `fn_NO_Fault`, `fn_NO_Alarm`, `fn_download`. And `sub_08005938`
references the entire 96-item settings menu — it is the main menu table/renderer.

### Recovered menu model
- **`reference/string_catalog.txt`** — ordered string blobs (the menu tree).
- **`include/inv/hmi_menu.h`** — 95-item settings menu as an ordinal enum.
- Rebuild guidance: mirror the original — one ordered string table indexed by a
  menu enum (`inv_menu_item_t`).

### Next tooling steps
1. Name the menu *renderers* (functions referencing the big menu tables, e.g.
   `sub_08005938`) and follow their call graph to the per-item handlers.
2. Jump-table (TBB/TBH) decoding for switch dispatch.
3. `reference/ghidra_rename.py` applies the names in Ghidra.
