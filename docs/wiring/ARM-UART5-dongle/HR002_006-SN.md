# HR 2-6 — SN (device serial number)

> **Dongle Modbus**, holding register (func `0x03`/`0x06`). Authoritative. See the [index](registers.md).

| reg | name | note |
|---|---|---|
| HR 2-6 | SN[0..9] | 10 ASCII bytes (`'0'-'9'`, `'A'-'Z'`), 2 per register |

e.g. `AB12345678` → SN[0]=0x41('A') … SN[9]=0x38('8').

## Side-effects of writing

**Persisted to the config flash** (the ARM owns settings storage,
[`docs/21`](../../21-arm-config-flash.md)/[`docs/23`](../../23-arm-config-writer.md)).
This is one of the **only two** blocks writable with `0x10` (write-multiple) — the
other is the time (HR 12-14). The 10-byte SN is also what rides every dongle frame
(see [index](registers.md)); changing it changes the SN echoed in responses.

**Request-SN matching (OSS decision, T12).** Every dongle frame carries a 10-byte SN
in its header. Ours runs with `check_sn` **off**: the SN on an incoming request is
echoed back but not required to match our stored SN, so a request addressed to the
right Modbus address is always served. Whether the factory *rejects* a frame whose
SN does not match its own is **not observable in this harness** (the SN-check path, if
any, sits on the factory's **dongle UART5** slave task, which the sim does not
schedule — a separate factory-dongle harness, not the T02 USART2 work, which is
done); until that can be captured we do not add a silent-drop-on-SN-mismatch that
could strand a correctly addressed dongle. See
[`docs/31`](../../31-factory-quirks.md) "OSS behaviour decisions".

## Test coverage

_Tests that exercise these registers. **Keep this list current when you add or change a test** (see [AGENTS.md](../../../AGENTS.md))._

- **HR 2-6 (SN):** echoed into the DSP config-frame header — [`test_dsp_config.c`](../../../tests/test_dsp_config.c) ("SN in header"). Every dongle transaction in the sim tests also carries a 10-byte SN, but `check_sn` is off so it is only echoed.
- **SN write/read-back (T24c):** the SN is set with a **write-multiple (`0x10`)** to HR 2-6 and read back over `0x03` — black-box on both images in [`test_arm_sim.py`](../../../tests/test_arm_sim.py) `test_sn_write_read_back` (via the harness `ModbusMaster.write_sn`/`read_sn`, [`arm_sim_modbus.py`](../../../tests/arm_sim_modbus.py)).
- **SN persistence (T24c):** the factory journals the `0x10` SN write to the config flash and restores it after a power cycle — [`test_arm_sim_factory_only.py`](../../../tests/test_arm_sim_factory_only.py) `test_persists_sn_across_cold_boot` (write → flush → cold boot → read back). **Ours does the in-session round-trip but does not yet persist the SN** (HR 2-6 are not in the pinned `SETTINGS_MAP`; the factory stores it in a slot-0 record whose exact payload offset vs ComAddr still needs pinning) — a recorded follow-up (docs/39 T24c).
